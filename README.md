# docsign

进程内文档签批推进库（Go）。正文、办理历史与签章附件全部保存在进程内，由上层直接调用。

## 能力

- `CreateDocument(docID, steps, body)`：创建文档，固定 2–10 个串行步骤（审批 / 签署），每步指定唯一办理人。
- `ReplaceBody(docID, body)`：替换正文并开启新轮次，全部步骤重新办理；旧轮次成功记录保留为历史。
- `Handle(req, gen)`：办理指定轮次、指定步骤。审批即时完成；签署在锁外调用 `gen` 生成签章附件，不阻塞其他操作。
- `Progress(docID)`：返回某一时刻完整一致的快照（正文、轮次、当前步骤、历史）。

## 关键语义

- 办理请求必须携带目标轮次与步骤；换版后迟到的旧轮次结果作废（`ErrStaleRound`），既不推进新轮次也不补记历史。
- 同一 `RequestID` 只用于同一业务命令：成功请求重试返回原结果（跨步骤、跨轮次均不重复推进、不重复生成）；生成中的并发重试共享同一次生成；生成失败不推进，可用原标识重试。
- 签章附件与「轮次正文 + 签署人 + 正文 SHA-256」绑定；历史中的摘要与附件在换版后不可变。
- 正文上限 1MiB；单进程并发安全，慢签章不阻塞换版、查看与其他文档办理。
